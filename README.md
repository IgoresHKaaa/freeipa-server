# ️ FreeIPA Web UI — Руководство по интерфейсу

## Запуск и проверка

```bash
docker compose up -d
docker compose ps
```

## Проверка Kerberos и API:

```bash
docker exec -it freeipa-server kinit admin
docker exec freeipa-server ipa ping
curl -fsS https://freeipa.study.dev-dom.oraclesiebelcrm.com/ipa/ui/ >/dev/null
```

## TLS и Certbot

- Certbot хранит сертификаты в certbot-etc. Дополнительный Nginx использует 8080/8443, потому что основной FreeIPA напрямую занимает 80/443

## Пользователи (Users)

```bash
docker run --rm freeipa/freeipa-server:rocky-9-4.13.1 \
cat /etc/pki/tls/cert.pem > nginx/freeipa-ca-bundle.crt
chmod 644 nginx/freeipa-ca-bundle.crt
docker compose -f docker-compose.certbot.yml up -d
docker compose -f docker-compose.certbot.yml ps
docker compose -f docker-compose.certbot.yml exec certbot certbot certificates
```

# Firewall

| Порт | Назначение | Доступ |
|---:|---|---|
| 80/tcp | HTTP redirect | Интернет |
| 443/tcp | HTTPS | доверенные сети |
| 53/tcp,udp | DNS | DNS |
| 88/tcp,udp | Kerberos | доменные клиенты |
| 389/tcp | LDAP | доменные клиенты, если нужен LDAP |
| 636/tcp | LDAPS | доменные клиенты |
| 464/tcp,udp | смена Kerberos-пароля | доменные клиенты |

## Подключение Linux-клиента

На клиенте должны работать DNS и время:

```bash
sudo apt install freeipa-client
sudo ipa-client-install \
  --domain=study.dev-dom.oraclesiebelcrm.com \
  --realm=STUDY.DEV-DOM.ORACLESIEBELCRM.COM \
  --server=freeipa.study.dev-dom.oraclesiebelcrm.com \
  --mkhomedir
```

Проверка:

```bash
id admin
kinit admin
ipa ping
```

## Основное вкладки

| Создать пользователя | Идентификация → Пользователи |
| Добавить хост в домен | Идентификация → Узлы | 
| Разрешить SSH только определённой группе | Политика → HBAC | 
| Дать sudo-права группе | Политика → Sudo |
| Настроить автомонтирование NFS | Политика → Automount | 
| Добавить SSH-ключ пользователю | Идентификация → Пользователи → SSH-ключи | 
| Настроить 2FA | Аутентификация → OTP |

| Подключить Active Directory | IPA-сервер → Trusts |
| Добавить реплику сервера | IPA-сервер → Replication |


## Идентификация (Identity)

Управление всеми объектами идентичности в домене FreeIPA из единой точки.

### Пользователи (Users)

Управление учётными записями пользователей: создание, блокировка, сброс паролей,
управление атрибутами (имя, email, телефон, должность, SSH-ключи).

| Подраздел | Описание |
|-----------|----------|
| Активные пользователи | Действующие учётные записи |
| Неподтверждённые | Ожидают подтверждения email/администратором |
| Хранимые пользователи | Заархивированные/неактивные записи |

## Узлы (Hosts)

Управление клиентскими машинами, присоединёнными к домену. Хранит SSH-ключи хостов,
их группы и атрибуты.

## Службы (Services)

Управление сервисными принципалами Kerberos (HTTP, NFS, LDAP и т.д.).

## Группы (Groups)

Создание групп пользователей и хостов для массового управления правами.

| Тип группы | Назначение |
|------------|------------|
| POSIX-группы | Стандартные группы Linux |
| Не POSIX | Группы только для политик FreeIPA |
| Группы хостов | Объединение машин для политик HBAC/sudo |
| Группы служб | Объединение сервисов |

### Представления ID (ID Views)

Альтернативные отображения UID/GID/имён для конкретных хостов.

### Автоучастник 

Автоматическое создание учётных записей при первом входе пользователя
из доверенного домена (например, Active Directory).

### Subordinate IDs

Управление диапазонами подчинённых UID/GID для контейнеров и user namespaces.

### System Accounts

Системные учётные записи (root), которые не должны управляться
вручную, но видны в каталоге.

## Политика (Policy)

Определение политик аутентификации и авторизации для идентичностей в домене.

### HBAC 

Контроль доступа на основе хостов. Определяет кто, к каким хостам
и через какие службы может подключаться.

!!! По умолчанию существует правило allow_all, разрешающее всем всё.

### Sudo

Централизованное управление правилами sudo.

| Объект | Описание |
|--------|----------|
| Sudo правила | Кто может выполнять какие команды на каких хостах |
| Sudo команды | Группы команд |
|Sudo категории | Категоризация команд |

### SELinux

Управление контекстами и политиками SELinux для пользователей и хостов.
Позволяет задавать SELinux-маппинги для учётных записей.

### Automount (Автомонтирование)

Централизованная настройка automount для NFS и других ФС.
Пользователи получают домашние каталоги автоматически при входе.

### Kerberos Ticket Policy

Политики Kerberos-билетов: время жизни, максимальное продление, требования.

## Аутентификация (Authentication)

Настройка методов и политик аутентификации пользователей.

Настройка двухфакторной аутентификации через одноразовые пароли. 

### Политики паролей

- Минимальная длина и сложность пароля
- История паролей
- Время до истечения срока действия
- Блокировка после неудачных попыток

## Сетевые службы (Network Services)

Управление сетевыми сервисами, интегрированными с FreeIPA.
 
### DNS

Встроенный DNS-сервер (на базе BIND). Управление зонами и записями прямо из UI.

### SSH

Централизованное хранение SSH-ключей пользователей и хостов.
Автоматическая публикация SSHFP-записей в DNS.

### NTP

Настройка синхронизации времени через Chrony/NTPD — критично для Kerberos.

## IPA-сервер (IPA Server)

Администрирование самого сервера FreeIPA.

### Configuration

Общие настройки домена: Kerberos realm, поисковые базы, настройки по умолчанию.

### Replication

Настройка мультимастерной репликации между серверами FreeIPA для отказоустойчивости.

### Trusts 

Настройка доверия с другими доменами идентичности:

| Тип доверия | Описание |
|-------------|----------|
| Active Directory | Двустороннее/одностороннее доверие с AD | 
| IPA-to-IPA | Доверие между разными доменами FreeIPA | 

### Certificates 

Управление сертификатами через встроенный CA:
- Запрос и выпуск сертификатов
- Отзыв сертификатов
- Профили сертификатов

### Topology

Визуализация и управление топологией репликации серверов.
